# Engineering Discipline

- Understand the affected flow and existing contracts before coding.
- Avoid speculative systems and build only the active phase scope.
- Reuse existing project code before creating helpers or abstractions.
- Prefer standard-library and native platform capabilities.
- Use installed dependencies before considering a new dependency.
- Avoid unnecessary wrappers, services, factories, interfaces, and configuration layers.
- Keep the smallest correct change in the shared root-cause location.
- Add only the verification needed to catch a meaningful regression.
- Record a deferred ceiling only when a deliberate shortcut has a known limit.
- Architecture, security, correctness, financial integrity, transactions, and accessibility outrank minimalism.
